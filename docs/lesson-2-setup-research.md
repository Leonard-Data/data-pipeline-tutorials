# Lesson 2 setup: primary-source findings

Checked 30 October 2026. Scope: the learner's Windows / WSL machine, 16+ GB RAM reported, Docker not installed, budget deferred. Research was performed inline because no background-agent tool is available.

## Decisions and evidence
- **Separate Windows and Ubuntu responsibilities.** Microsoft documents administrator PowerShell installation, first-launch Ubuntu setup, restarts, and `wsl --list --verbose` for distribution mode. A distribution's VERSION 2 is different from the installed WSL software release reported by `wsl --version`. Source: https://learn.microsoft.com/en-us/windows/wsl/install
- **Check Docker's requirements independently.** Docker Desktop has its own supported Windows builds/architectures, virtualization/SLAT and memory prerequisites, and WSL version requirements. Do not infer Desktop eligibility solely from WSL being installable. Use the live matrix rather than copying a stale list into the lesson. Source: https://docs.docker.com/desktop/setup/install/windows-install/
- **Do not promise free professional use.** Docker's terms distinguish personal/education/small-business eligibility from other professional/government use. No paid provisioning is approved. Source: https://docs.docker.com/desktop/setup/install/windows-install/#start-docker-desktop
- **One Docker installation.** Desktop's WSL backend and distribution integration expose the CLI inside Ubuntu. Docker warns against a second Engine/CLI installation directly in the WSL distribution. Select Linux containers and enable Ubuntu integration. Source: https://docs.docker.com/desktop/features/wsl/
- **Linux-home project files.** Docker recommends Linux-filesystem storage for bind-mounted source, for performance and Linux file-change events. Source: https://docs.docker.com/desktop/features/wsl/best-practices/
- **Git via Ubuntu's package manager.** The Git project's Debian/Ubuntu instructions use the distro package manager. Source: https://git-scm.com/install/linux
- **Supported Python baseline, not newest Python by default.** Python 3.12 remains in security support, with scheduled end of life in October 2028 at the time checked. dlt's installation guide documents Python 3.10–3.14. This supports choosing 3.12 for the setup exercise, not asserting compatibility for all adapters/integrations. Sources: https://devguide.python.org/versions/ and https://dlthub.com/docs/reference/installation
- **uv owns interpreter selection, environment, and dependency lock.** uv manages/downloads Python; project requirements live in `pyproject.toml`, installed packages in `.venv`, and exact dependency resolution in `uv.lock`. Commit the lock; do not hand-edit it or commit the virtual environment. Sources: https://docs.astral.sh/uv/guides/install-python/ and https://docs.astral.sh/uv/guides/projects/
- **Installer trust boundary.** Astral publishes the installer and explicitly offers inspection before execution. The lesson saves it to a fresh temporary file, displays it, and runs that same file only after the learner approves it; no sudo or execution-policy bypass for uv. Source: https://docs.astral.sh/uv/getting-started/installation/
- **Locked sync is not frozen sync.** `--locked` errors if the lock is outdated instead of updating it. `--frozen` skips that freshness check. `uv sync` is exact by default and removes extraneous packages, so never target system/shared Python. Source: https://docs.astral.sh/uv/concepts/projects/sync/
- **Nondestructive reconstruction.** `UV_PROJECT_ENVIRONMENT` selects another environment path, relative to the project for a relative value. Use a new `.venv-replay` directory, guarded against existing paths, without deleting `.venv`. Reject a pre-existing override before initial project creation because it can direct synchronization elsewhere. Source: https://docs.astral.sh/uv/concepts/projects/config/#project-environment-path
- **Isolation check.** Python documents `sys.prefix != sys.base_prefix` as a virtual-environment test. It alone does not prove the correct project, Python patch, or dependency set; inspect those separately. Source: https://docs.python.org/3/library/venv.html#how-venvs-work
- **Compose is bundled.** Docker Desktop includes Engine, CLI, and Compose. Use `docker compose`, not a second standalone legacy install. Source: https://docs.docker.com/compose/install/
- **Different Docker checks prove different things.** `docker --version` is client availability; successful `docker version` includes the server. A disposable hello-world run checks basic container execution, not databases, persistence, or the factory stack. `--rm` removes the exited container, not its image. Sources: https://docs.docker.com/engine/install/ubuntu/ and https://docs.docker.com/reference/cli/docker/container/run/

## Instructor choices, not vendor guarantees
- Reserve 20 GB free host-drive space as conservative headroom for small later labs. This is not Docker's minimum, a measured capacity requirement, or a promise that the full stack fits.
- Use dlt core only to make dependency locking concrete. Drivers, destinations, Dagster, dbt, and dashboard compatibility are not installed or validated here.
- Select Python minor 3.12 and record the actual patch. The dependency lock does not pin the OS, Docker image, Python binary/patch, or external data.

## Authoring verification boundary
The authoring host runs Linux / Python 3.14.4, has uv, and has no Python 3.12, Docker, or PowerShell executable available. A temporary config-only `uv init --bare --vcs none --python 3.12 --no-python-downloads` succeeded; explicit `uv python pin 3.12 --no-python-downloads` created `.python-version`, with an expected warning that 3.12 is not installed. No interpreter or dependency downloads were performed.

Browser tests execute the exact lesson environment-check script in disposable standard-library virtual environments and verify rejection of the unisolated host interpreter. Bash examples are syntax-checked; the real guarded mkdir/cd prefix is tested against fresh/existing directories and an unsafe environment-path override without executing installation commands. These do not certify the learner's Windows setup, target Python/dlt installation, or Docker smoke test. The exit report requests that evidence.
